# 設計

## 構成

- `src/lib/csv.ts`: サービス別ヘッダー定義、文字コード、入力検証、共通形式への変換。
- `src/lib/engine.ts`: 原子的取込、分類、照合、整数集計。
- `src/lib/types.ts`: 共通取引・分類・ルール・照合・監査・同期状態。
- `src/lib/store.ts`: ローカルSQLite / 認証済みSupabase、世代管理、暗号化、同期排他。
- `src/lib/auth.ts`: Supabaseセッションのサーバー検証、開発専用ローカルモード、Origin検証。
- `src/lib/reports.ts`: Sheetsと補助Excelで共通の表データ。数式注入を防止。
- `src/lib/google.ts`: OAuth、暗号化トークン、スプレッドシート管理印、再試行可能な置換同期。
- `src/app/api/[...path]/route.ts`: サーバー認可・入力検証・ユーザー操作。
- `src/app/api/jobs/daily/route.ts`: 秘密ヘッダー認証の日次Sheets同期。

## 原本と共通DB

取引の正規化後データに、原本行・元ヘッダー・行番号をAES暗号文として紐づけます。ファイル全体のSHA-256をバッチに保存します。取込時の元Excelの金額・売上・メモは、新しい取引として取り込みません。

SQLiteとSupabaseの両方で正本状態と各取引を暗号化して保存し、取引ID/指紋を一意キーにします。共通金融フィールドは暗号化された `Transaction` に存在します。Supabase上で各金額フィールドを直接SQL集計する方式ではなく、サーバーで認可・復号してエンジンで集計します。

金額は安全な整数、1件最大1兆円。合計も整数精度をチェックします。方向をout/in、取引種別をpurchase/refund等に分離します。日付は年月日で扱い、入力の時刻があっても取引日のまま保存します。

## 集計

購入支出 = 除外されていない purchase / refund / fee の出金額 − 入金額。

銀行出金 = 銀行サービスの出金（引落不能を除く）。資金移動はtransfer / card_settlement / chargeの出金側です。借入元本・投資・税金は購入支出に入りません。これは税務上の経費計算ではありません。

未照合・未分類・重複候補があれば暫定表示。未判定の購入は「その他」に仮置きし、購入支出に含めます。正規化利用先の一致は用途が同じである根拠ではないので、承認済みルール以外は分類を確定しません。

## Excel由来分類

2025年116、2024年104、2023年78の選択可能分類。合計298件。IDは固定名前空間UUIDv5と年度・元セルで決定します。親グループも固有IDを持ち、小計行は選択不可です。ユーザー追加の分類・項目、既存の名称・所属変更は状態に別保存し、元Excelの分類IDと来歴を保持します。交通費の2つの小計や所得税の重複は統合しません。

小計直前の項目をグループとして保存します。2025年のクラウドファンディングやshopifyは、元のSUM範囲に含まれない場合でも名前を保持します。小計がない過去年の項目は独立グループです。利用先らしいラベルを推測で再分類せず、元Excelの行をそのまま分類として保持し、取引側でmerchant_idを別管理します。

色の元情報（RGB/theme/indexed/tint）をJSONに保持。RGB/themeを月別出力に反映します。テーマが特殊な場合やindexed色は近似表示になる場合があります。Excel側の色を変更しても自動再移行はしません。

## 監査・制約

変更イベントと更新前後の分類ID等を記録し、全状態の世代履歴を保持。正常な操作では原本を削除しません。変更履歴の閲覧・暗号化バックアップ・不足明細の復旧が可能です。

全状態をサーバーで読むため、現段階は少人数・個人利用の規模を想定します。1ファイル5MB/20,000行、DB RPCは20万件/暗号文50MBに制限。金融機関の正式な取得権限が確認されるまで自動取得コネクターは実装しません。別の売上ツールが出力するGoogleスプレッドシートは、既存OAuthトークンを使ってGETで読み、暗号化された照合用参照行として保存します。参照行は支出取引や売上集計に変換せず、同日・同額または同日・類似名の候補だけを作ります。売上ツールのコードとシートは変更せず、利益への自動減算も行いません。
